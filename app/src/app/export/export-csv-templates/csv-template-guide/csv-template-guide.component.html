Columns

  • The template comes in a fixed order: Public ID, Active, then the type's own fields, then one column per Multi Data Section field, grouped by section. That is the same order a CSV export produces, so an export can be re-imported unchanged.
  • A header reads Label [MDS-Section] [field_name] — the last bracket group is the field name. Plain field_name headers also work, and both notations may be mixed.
  • Keep the header row and each column's field name — the import maps a column by that name, so renaming it breaks the mapping.

Multi Data Sections: one object over several rows

Only relevant if the selected type has a Multi Data Section.

web-01 has three network interfaces and two disks, so it occupies three rows. Rows 2 and 3 leave Public ID empty to continue the same object, and the disk columns stay blank once that section runs out of entries. db-01 has no Multi Data Section entries and app-01 has exactly one per section, so a single row is enough for both. Blank cells are genuinely empty cells.
Public ID [public_id] Hostname [hostname] NIC Name [MDS-Network Interfaces] [nic_name] NIC IP [MDS-Network Interfaces] [nic_ip] Slot [MDS-Disks] [disk_slot]
1 web-01 eth0 10.0.0.11 1
eth1 10.0.1.11 2
mgmt 192.168.50.11
2 db-01
3 app-01 eth0 10.0.0.13 1
  • An object needs as many rows as its largest Multi Data Section has entries. Fill one entry per row.
  • An empty Public ID means "this row continues the object above". All identity and regular columns stay empty on those rows; only Multi Data Section columns carry data.
  • A row where all of a section's columns are empty adds no entry to that section. Entries are numbered automatically in file order — there is no column for it.
  • Give every Multi Data Section field its own column. Do not put a whole section into one cell as JSON.

Values

  • An empty cell means "no value" and the field's default from the type applies.
  • Quote any value containing a comma: "Rack 4, Row B".
  • Booleans accept true/false, yes/no and 1/0, case-insensitively.
  • For dates YYYY-MM-DD is safest; DD.MM.YYYY, YYYY/MM/DD, YYYY.MM.DD and the … HH:MM[:SS] variants also parse.
  • Save the file as UTF-8, comma-separated, with " as the quote character.

Before you import

  • Never leave Public ID empty on an object's first row — a column that is blank everywhere collapses the whole file into a single object.
  • Public ID is only a grouping key: new IDs are assigned on import unless you enable overwrite, which replaces the existing object with that ID instead.
  • Reference fields cannot be resolved from a CSV — those columns are imported empty.
  • A file containing only the header row is rejected; add at least one data row.
